# Local patches to vendored Qodo skills

The Qodo skills in `.claude/skills/` are vendored, so we don't edit them by hand:
- They were installed by commit `410c220`, "chore: add Qodo's codebase wisdom, review and review resolver skills for this project".
- `metadata.distribution: "skills-sh"` is in each `SKILL.md`.
- Each `agents/openai.yaml` starts "Generated by scripts/sync-adapters.mjs. Do not edit by hand."

A skill update (`qodo agents update`, see `.claude/skills/qodo-review/references/skill-updates.md`) or a re-sync of the adapters will rewrite these files. **After any update, re-check every patch below and re-apply it if it's gone.**

## Patch 1: `qodo-review` runs only when asked (PR #86, Qodo finding `69808cf1-03a0-4513-8256-adf53318aa70`)

**Why:** `qodo review` uploads the local diff, untracked files and session context to Qodo (`SKILL.md:17,284-289`). The skill tells the agent to run "light background checkpoints while coding" (`SKILL.md:3,31,35`), and both adapters let the agent start it without being asked. So unpublished code could leave the machine without the user asking for a review. Qodo flagged this on PR #86 at `b41eb40` (`00-finding.md`).

With this patch:
- **Claude Code** and **Codex** still run the skill when the user asks for it (for example `/qodo-review`, "run qodo review" or `$qodo-review`).
- Neither agent starts it on its own.

```diff
--- a/.claude/skills/qodo-review/SKILL.md
+++ b/.claude/skills/qodo-review/SKILL.md
@@ -1,6 +1,7 @@
 ---
 name: qodo-review
 description: Review local changes with Qodo during substantive coding milestones and before a PR or completed-work handoff. Use light background checkpoints while coding, collect and assess findings with session context, and run a final review before handing off. Also use for "review my local diff", "pre-PR review", or "run qodo review". Use qodo-review-resolver for findings already posted on a PR.
+disable-model-invocation: true
 owner: Qodo
 metadata:
   vendor: qodo
--- a/.claude/skills/qodo-review/agents/openai.yaml
+++ b/.claude/skills/qodo-review/agents/openai.yaml
@@ -5,4 +5,4 @@ interface:
   brand_color: "#6D4AFF"
   default_prompt: "Use $qodo-review to review my local changes before I push them."
 policy:
-  allow_implicit_invocation: true
+  allow_implicit_invocation: false
```

**What each line does:**

| Line | Read by | Effect |
|---|---|---|
| `disable-model-invocation: true` | Claude Code | The skill runs only when the user calls it. |
| `allow_implicit_invocation: false` | Codex | Codex won't start the skill by itself. |

**Check after an update:**
```sh
grep -n '^disable-model-invocation: true$' .claude/skills/qodo-review/SKILL.md
grep -n 'allow_implicit_invocation: false' .claude/skills/qodo-review/agents/openai.yaml
```
Both must print one line. If either prints nothing, re-apply the diff above.

**Not patched, on purpose:** `qodo-codebase-wisdom` and `qodo-review-resolver` still allow implicit invocation (`agents/openai.yaml:8` in each). Neither uploads local source, and the finding names only `qodo-review`.

**Upstream:** this is a local fix to a vendored file. [A] The lasting fix is for Qodo to ship the skill without implicit invocation, or with a consent step before upload.
